# CI/CD Setup Guide

## Overview

This project uses GitHub Actions for CI (testing) and CD (deployment). The frontend is deployed to GitHub Pages. The backend runs on Convex cloud and is deployed automatically as part of CD.

---

## Step 1: Configure the Convex Production Dashboard

All secrets that the backend needs at runtime are set **directly in the Convex dashboard** — never in GitHub or in code.

Go to: [dashboard.convex.dev](https://dashboard.convex.dev) → select your **production** deployment → **Settings → Environment Variables**

Add the following:

| Variable | Where to get it |
|----------|----------------|
| `AUTH_GOOGLE_ID` | Google Cloud Console → APIs & Services → Credentials → your OAuth Client ID |
| `AUTH_GOOGLE_SECRET` | Same OAuth client → Client Secret |
| `JWKS` | Generated by Convex Auth — run `npx @convex-dev/auth` locally and copy the output |
| `JWT_PRIVATE_KEY` | Generated by Convex Auth — same command as above |
| `GEMINI_API_KEY` | Google AI Studio → API Keys |
| `SITE_URL` | Our GitHub Pages URL |

> These variables are only visible inside the Convex runtime. They are never exposed to the browser or to GitHub.

---

## Step 2: Configure GitHub Repository Secrets

These are used by GitHub Actions during the build and deployment process. They are never printed in logs or exposed in the built files.

Go to: GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**

Add the following:

| Secret | Value |
|--------|-------|
| `CONVEX_DEPLOY_KEY` | Convex dashboard → your production deployment → Settings → Deploy Keys → Generate |
| `VITE_CONVEX_URL` | Production Convex URL |
| `SITE_URL` | GitHub Pages URL |

> `VITE_CONVEX_URL` is the only variable baked into the frontend build. It is the public Convex endpoint — not a secret per se, but kept here to avoid hardcoding environment-specific values in the repo.

---

## Step 3: Configure Google Cloud Console

Go to: [console.cloud.google.com](https://console.cloud.google.com) → APIs & Services → Credentials → your OAuth 2.0 Client ID

Add these under **Authorized JavaScript origins**:
```
https://<your-org>.github.io
```

Add these under **Authorized redirect URIs**:
```
https://dutiful-dinosaur-826.convex.site/api/auth/callback/google
```

> The redirect URI points to Convex, not GitHub Pages. Google sends the auth code to Convex, which then redirects the user back to `SITE_URL` (your frontend).

## How CI Works

**File:** `.github/workflows/ci.yml`

Triggers on: pull requests to `main` or `dev`, and pushes to `main`

Steps:
1. Installs dependencies (`npm ci`)
2. Builds the frontend (`npm run build`) — catches TypeScript and build errors early
3. Runs tests (`npm test`)

> CI does not deploy anything. It only validates that the code compiles and tests pass.

---

## How CD Works

**File:** `.github/workflows/cd.yml`

Triggers on: pushes to `main`

Steps:
1. Installs dependencies
2. Installs the Convex CLI globally
3. **Deploys the Convex backend** using `CONVEX_DEPLOY_KEY` — pushes all functions, schema, and auth config to production
4. **Sets `SITE_URL`** on the Convex backend so OAuth redirects back to the correct frontend URL
5. **Builds the frontend** with `VITE_CONVEX_URL` injected at build time
6. Uploads the built `frontend/dist` folder as a GitHub Pages artifact
7. Deploys it to GitHub Pages

> The only value baked into the frontend bundle is `VITE_CONVEX_URL`. Everything else (Google keys, Gemini key, JWT keys) stays on the Convex server and is never included in the build.

---

## Secret Exposure Rules

- **Never** put `AUTH_GOOGLE_SECRET`, `GEMINI_API_KEY`, `JWT_PRIVATE_KEY`, or `JWKS` in GitHub secrets or in any frontend code
- **Never** prefix backend-only secrets with `VITE_` — anything with that prefix gets bundled into the JavaScript that users can download
- **Never** commit `.env` or `.env.local` files — they are gitignored
- The only value safe to expose publicly is the Convex URL (`VITE_CONVEX_URL`), as it is a non-sensitive endpoint
